# Анализ управляемости UtrIskra

*Цель: понять, чем в проекте можно управлять, где эти настройки живут сейчас,
и что имеет смысл вынести в веб-панель. Составлено по полному разбору
`runners/` (15 раннеров), `services/` (13 сервисов + test_availability),
`utils/prompt_utils.py`, `config.py` и БД. Дата: 2026-07-16.*

---

## 1. Конвейер публикации и его «ручки»

Каждая публикация проходит пять ступеней. На каждой — свой набор параметров:

```
[1] ТЕМА/ПРОМПТ        prompt-файл или хардкод + плейсхолдеры
      ↓                    ({current_date}, {random_theme}, {random_category}, {random_seed})
[2] LLM (Gemini)       модель, temperature, ротация ключей, SOCKS5-прокси,
      ↓                    fallback на локальную LLM (qwen3.7-max-thinking)
[3] ГЕНЕРАТОР          модель/движок, aspect ratio / size, steps, cfg/guidance,
      ↓                    negative prompt, seed, use_pe, поллинг/таймауты
[4] ПОСТ-ОБРАБОТКА     водяной знак «БУКВА dd.mm.yyyy» (Roboto, правый нижний угол),
      ↓                    для MidJourney — кроп сетки 2×2 (всегда позиция 1)
[5] ПУБЛИКАЦИЯ + УЧЁТ  send_photo/send_video в TARGET_CHAT_ID (без caption),
                           ретраи у части раннеров, запись в SQLite
```

## 2. Три слоя конфигурации сегодня

| Слой | Что там | Управляется |
|---|---|---|
| **.env** (~24 переменных) | ключи 10 API, `PROXY_URL`, `TELEGRAM_TOKEN`, `TARGET_CHAT_ID`, `TELETHON_*`, URL 4 локальных API (192.168.0.60:8000-8003), `QWEN_CHAT_API_URL`, `FALLBACK_LLM_*`, пути, `WEB_HOST/WEB_PORT` | правкой файла + рестарт |
| **runners/prompts/*.txt** (12 файлов) | system/user-промпты для LLM | правкой файлов |
| **Хардкод в коде** (самый большой слой) | модели, все параметры генерации, temperature, буквы водяных знаков, ретраи, таймауты, поллинг, видео-промпты, позиция кропа | только правкой кода |
| **Веб-панель** (после внедрения) | вкл/выкл расписания, время запуска, ручной запуск, история/логи | UI ✅ |

**LLM-слой (общий для всех):** `gemini-3.5-flash` захардкожен в URL
(`services/gemini_service.py:63`, рядом 7 закомментированных моделей — смена
модели сейчас = правка кода). Ротация `GEMINI_API_KEYS`, 503 → 3 попытки × 10 с,
429/невалидный ключ → следующий ключ, всё исчерпано → fallback на
`FALLBACK_LLM_MODEL` (qwen3.7-max-thinking, таймаут 600 с, без прокси).

**Формат промпт-файлов** (`utils/prompt_utils.py`): блоки
`---SYSTEM_PROMPT---…---END_SYSTEM_PROMPT---` и `---USER_PROMPT---…---END_USER_PROMPT---`,
плейсхолдеры `{current_date}`, `{random_theme}` (1..max_theme),
`{random_category}` (1..max_category), `{random_seed}` (1..999999) — только в user-части.
Три поколения структуры: простая (10 тем) → многошаговая (qwen/zimage/qwen_chat)
→ со «стилевым якорем» (dalle/ernie/hidream: случайная категория из 14–15 + seed + 50 концепций;
у hidream — классификация MINIMALIST / NAMED-STYLE / REGULAR).

## 4. Находки (проблемы и странности)

1. **`sys.exit(1)` в `gemini_image_service.py`** при исчерпании всех ключей.
   Для cron-скрипта это было «завершить процесс», внутри веб-приложения —
   аварийный сценарий (запуск идёт в отдельном потоке, но SystemExit — не
   Exception, и обработка ошибок его не ловит штатно). Заменить на исключение.
2. **Пустой промпт при полном отказе LLM**: `gemini_service.generate_prompt()`
   возвращает `""`, если и Gemini, и fallback недоступны. Ни один раннер это
   не проверяет — пустая строка уйдёт в генератор изображений.
3. **`best_image_video_runner`**:
   - изображение загружается на **catbox.moe**, хотя в `MidjourneyService.upload_image()`
     уже реализована загрузка на CDN Kolersky (и CLAUDE.md прямо называет
     catbox нежелательным);
   - шаг `create_image_to_image_task(...)` — мёртвый код: результат не используется;
   - `iter_messages(offset_date=week_ago)` в Telethon отдаёт сообщения **старше**
     недели, а не «за последнюю неделю» — семантика, вероятно, инвертирована;
   - реакции суммируются без различия типов (👍 и 👎 равнозначны);
   - единственный раннер, не пишущий в БД.
4. **Коллизия водяного знака «S»** — `daily_runner` и `stability_runner` помечают
   изображения одинаково; в галерее оба определяются корректно (разные префиксы
   файлов), но на самих картинках не различить.
5. **`print()` вместо logging в `gemini_service.py`** (10 вызовов) — диагностика
   ротации ключей не попадает в логи запусков панели (только stdout → journald).
6. **`services/test_availability.py` мёртв**: старые endpoints FusionBrain
   (`models` vs `pipelines`) и пустые ключи, захардкоженные в файле.
7. **Yandex `size=1792x1024` игнорируется API** — модель aliceai-image-art-3.0
   отдаёт максимум 1344×768 (см. память проекта); запрошенный параметр создаёт
   ложное ощущение контроля.
8. **Дубли кода**: `create_image_path()` скопирован в `daily_runner` и
   `gemini_image_runner` (в `utils/image_utils.py` есть общая версия);
   `daily_runner` почти полностью дублируется `stability_runner`.
9. **Расчёт позиции водяного знака** в `add_date_to_image` оценивает ширину
   текста как `font_size × len(text)` (моноширинное допущение) — на узких
   шрифтах текст уезжает от правого края.
10. **`runners/scheduler.py` и `main.py`** — legacy, заменены панелью
    (импорт `send_yandex_story` уже починен, но файлы больше не нужны).

## 5. Ключевое наблюдение: 11 раннеров — это один раннер

11 из 15 раннеров структурно идентичны:

```
prompt-файл → Gemini → service.generate_image(параметры) → водяной знак → БД → send_photo
```

Различия — только данные: путь к промпт-файлу, max_theme, temperature, класс
сервиса и его параметры, буква знака, наличие ретраев Telegram. Уникальную
логику имеют только `midjourney` (кроп сетки), `midjourney_video` (двухэтапная
генерация) и `best_image_video` (Telethon-реакции).

**Следствие:** вместо того чтобы прикручивать настройки к 15 файлам по
отдельности, правильный ход — один параметризованный пайплайн + конфиг
`storage/webapp/generators.json`, который и станет содержимым «настроек»
в панели. Любая новая настройка (dry-run, caption, знак, ретраи) делается
один раз, а не 15.

## 6. Дорожная карта настроек в панели

### Этап 1 — без рефакторинга раннеров (быстрые победы)
| Фича | Что даёт | Сложность |
|---|---|---|
| **Редактор промпт-файлов** в UI: список 12 файлов, textarea, валидация маркеров, бэкап предыдущей версии при сохранении | Главный инструмент влияния на контент — сейчас только через ssh | низкая |
| **Модель Gemini в настройку** (env/JSON + выпадающий список в UI, включая fallback-модель) | Смена модели без правки кода (сейчас — комментарии в коде) | низкая |
| **Страница «Здоровье»**: `health_check()` 4 локальных API, доступность Kandinsky, число ключей Gemini, проверка Telegram-токена | Видно, что сломано, до ночного запуска | низкая |
| **Перенос хардкод-промптов** daily/gemini_image в prompt-файлы | Все 14 LLM-раннеров редактируются единообразно | низкая |
| `print()` → logging в gemini_service | Ротация ключей видна в логах запусков панели | тривиальная |

### Этап 2 — единый пайплайн + generators.json
- Общий `runners/pipeline.py` (генерация → знак → БД → публикация) и перевод
  11 типовых раннеров на него; параметры per-генератор в
  `storage/webapp/generators.json` с редактированием из UI:
  temperature, max_theme, aspect ratio/size, steps, cfg/guidance,
  negative prompt, model, use_pe, буква и формат знака, ретраи TG.
- Валидация: у каждого сервиса свой набор допустимых полей (описать в реестре).

### Этап 3 — контроль результата
- **Dry-run**: «Сгенерировать без публикации» → черновик в панели →
  кнопки «Опубликовать» / «Перегенерировать» / «Удалить». Требует этапа 2
  (публикация отделена от генерации).
- **Тестовый канал**: `TARGET_CHAT_ID` per-генератор + отдельный канал для черновиков.
- **Caption** публикаций (шаблон с названием генератора/темой).
- MidJourney: выбор позиции кропа или публикация выбранного из 4 вариантов в dry-run.

### Этап 4 — учёт и надёжность
- Расширение схемы БД: колонки `generator`, `status`, `telegram_message_id`,
  `duration`, `cost/requests` — статистика и связь с реакциями.
- Починка `best_image_video`: период выборки, kolersky вместо catbox,
  учёт типов реакций, запись в БД.
- Единые настройки ретраев/таймаутов; лимит параллельных генераций.
- Удаление legacy: `main.py`, `runners/scheduler.py`, починка/удаление
  `test_availability.py` (заменяется страницей «Здоровье»).
